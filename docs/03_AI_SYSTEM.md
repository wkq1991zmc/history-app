# AI 互动系统的三层架构

这是项目最核心的技术-内容融合点。**接手时务必完整理解。**

---

## 6.1 第一层：剧情骨架（写死）

主线剧本、关键场景、历史节点、关键选择——这些**全部是编剧写死的**，AI 不参与生成。

格式：传统视觉小说脚本，结合选择树。

为什么写死：
- 节奏完全由编剧把控
- 历史细节不会出错
- 重要的情感时刻必须精雕细琢，不能交给概率

---

## 6.2 第二层：伙伴 AI 自由对话

**仅限阿萤（未来可能扩展到其他常驻伙伴）**。

### 触发时机
- 篝火旁、客栈夜里、长途行走中的停顿
- 重大事件后的"反应时刻"
- 玩家主动呼出（屏幕角落有一个"言"字按钮）

### 实现方式

每个对话节点写一张 **"状态卡"**，传给 AI 模型作为系统提示词。状态卡的完整模板与示例见 [`06_PROMPT_TEMPLATES.md`](06_PROMPT_TEMPLATES.md) §6.2。

状态卡核心字段：
- 时间 / 地点
- 她刚刚经历的事
- 她当下的情绪
- 她知道的事
- 她不会主动说的事（含两个秘密的当前隐藏状态）
- 她近期的伏笔（本节点可以漏的暗示）
- 对话轮数（不限 / X 轮）
- 玩家可中断状态

### AI 实现技术要点（给 Claude Code）

- 推荐模型：Claude Sonnet 4.6 或同等水平模型（中文文学性强）
  - **注：当前 history-app 接 qwen3.6-flash（阿里百炼），按 SETUP_GUIDE 决策 3 继续使用 qwen 体系，需要为 qwen 写适配的 prompt**
- 上下文需包含：
  1. 阿萤的总体人设（从 [`02_CHARACTERS.md`](02_CHARACTERS.md) 读取）
  2. 当前状态卡
  3. 玩家近 N 次重要选择
  4. 本次对话历史
- 必须有"硬约束检查"：模型生成的回复如果包含未来事件预言、违反人设、暴露未到时间的秘密 → 重新生成
- 对话保存到该玩家的存档中，影响后续状态

## 6.3 第三层：历史人物受限对话

**适用于荀彧、董承、关羽等史实人物**。

### 与第二层的关键差异

- **对话轮数硬限制**（通常 3—5 轮）
- **知识边界严格**——一张"知识边界卡"详尽列出此人在此时此地的全部认知边界
- **超出边界即终止**——AI 生成的回复如果触及此人当时不可能知道/不可能说的内容 → 重新生成或直接给一个回避回答

知识边界卡的完整模板与"荀彧·中平六年八月"示例见 [`06_PROMPT_TEMPLATES.md`](06_PROMPT_TEMPLATES.md) §6.3。

### 完整工作流（接手 Claude 注意）

1. 玩家触发与历史人物对话
2. 系统加载该人物的知识边界卡 + 当前历史背景上下文
3. AI 生成回复，过 **三道检查**：
   - 是否预言未来？
   - 是否违反人设？
   - 是否泄露其当时不可能知道的事？
4. 任意一道未过 → 重新生成（最多 3 次） → 仍未过 → 触发预设的回避回答
5. 轮数耗尽 → 触发预设的"剧情自然推走"对话

### 三道检查的实现路径（SETUP_GUIDE 阶段五自主决定）

> SETUP_GUIDE 明确：三道检查的具体实现——LLM 后置检查 / 规则系统 / prompt 工程让模型自我约束——由 Claude Code 根据 qwen 特性决定，重点是达到"不预言未来、不违反人设、不暴露未到时间秘密"的效果。

候选方案（待阶段五评估）：

| 方案 | 优点 | 风险 |
|---|---|---|
| 单轮 prompt + 自我约束 | 一次调用，便宜快 | qwen3.6-flash 自我约束能力可能不够 |
| 生成后用同模型做后置校验 | 实现简单 | 双倍 token，仍可能误判 |
| 规则系统兜底（关键词/事件年表黑名单） | 稳定可靠 | 维护成本高，灵活性差 |
| 混合（prompt 内置约束 + 关键词黑名单） | 兼顾 | 复杂度增加 |

## 6.4 三层架构在剧本中的标注规范

剧本里必须明确每段是哪一层：

```
【剧情骨架·写死】
（编剧手写的对话）

【伙伴自由对话·阿萤】
ⓘ 状态卡：[卡内容]
（玩家自由输入区域）

【历史人物受限对话·荀彧】
ⓘ 知识边界卡：[卡内容]
ⓘ 轮数：5
（玩家自由输入区域）
```

---

## 6.5 核心原则总结

> **AI 表演，规则系统裁判。**

- AI 负责生成符合身份的语言与情绪
- 规则系统负责判断：能不能说、说几轮、说完后剧情往哪走、属性如何变化
- 不要让 AI 自由决定剧情走向、属性、官职、日期、结果——任何会"影响后续叙事/数据"的判定都必须由结构化代码控制
